# AI fix-until-green loop that never converges

## 🎯 چالش / Challenge
یک حلقهٔ «اجرا کن ⇒ ایرادها را به مدل بده ⇒ بازنویسی ⇒ دوباره اجرا» روی کدِ تولیدشده، دور پشتِ دور **همان** تست‌ها را رد می‌کرد. برنامه در مرورگر درست بود؛ تست‌ها با فرضِ یک API ِ دیگر نوشته شده
بودند (خروجی `{year, month, day}` در تست، `{gy, gm, gd}` در کد). مدل هر دور چیزی بازنویسی می‌کرد و هیچ‌چیز تکان نمی‌خورد.

### علت (دو تا، هر دو در ابزار — نه در مدل)
1. **شواهدِ بریده:** خروجیِ تست به N نویسهٔ **آخر** کوتاه می‌شد و فهرستِ «ردشده‌ها» از همان دُم ساخته می‌شد. ردشده‌های اول — که `expected`/`actual` ِ گویا داشتند — بیرون می‌افتادند و مدل فقط
   پیامدها را می‌دید (`NaN`، «تاریخ نامعتبر»)، نه علت را.
2. **بی‌حافظگی:** حلقه نمی‌دانست دورِ قبل همین تست‌ها رد شده‌اند؛ همان درخواست را تکرار می‌کرد تا سقفِ دورها، و آخرش فقط «هنوز ایراد دارد» می‌گفت.

## 💡 راه‌حل / Solution
1. **اول خلاصه کن، بعد کوتاه کن.** هر ساختاری که به مدل می‌رود (نامِ تست‌های ردشده، expected/actual) از خروجیِ **کامل** استخراج شود؛ فقط متنِ خامِ نمایشی کوتاه شود.
2. **مقدارهای چندخطی را بخوان.** در TAP/YAML، `expected:` ِ یک شیء چند خط است؛ اگر فقط مقدارِ همان خط را بخوانی، مهم‌ترین تفاوت (نامِ کلیدها) گم می‌شود.
3. **حدسِ قطعی پیش از مدل.** کلیدهای expected و actual هیچ اشتراکی ندارند ⇒ «ناسازگاریِ شکلِ خروجی بینِ تست و کد». `does not provide an export named` / `is not a function` ⇒ «تست چیزی را می‌خواهد
   که کد ندارد». این را هم به مدل بده و هم به کاربر.
4. **ایستایی را بسنج.** مجموعهٔ نامِ ردشده‌های هر دور را نگه دار. اشتراکِ دو دورِ پشتِ هم ≠ ∅ ⇒ **راهبرد عوض شود**: پرامپتی که فقط دربارهٔ همان تست‌هاست، شواهدِ مستقل می‌دهد («سناریوی مرورگر
   با همین کد سبز است»)، آنچه کد واقعاً export می‌کند را فهرست می‌کند و از مدل می‌خواهد **پیش از کد** بنویسد ریشه کدام طرف است (`ROOT: test|code|both`).
5. **ایست و اعتراف.** راهبردِ دوم هم همان مجموعه را تکان نداد ⇒ بایست و بگو «همگرا نشد — این تست‌ها، علتِ احتمالی این». دورِ بیشتر فقط هزینه است.
6. **حافظه بینِ اجراها.** ردشده‌های پایانِ اجرای قبل را نگه دار تا «دوباره امتحان کن» ِ کاربر از راهبردِ دوم شروع شود، نه از همان دورِ بی‌اثر.

## 🧪 نمونه کد (Anonymized)
```python
fail_hist = ([set(prev_failing)] if prev_failing else []) + [failing_names(report)]
diagnosed = set()
for n in range(1, max_rounds + 1):
    stuck = fail_hist[-1] & fail_hist[-2] if len(fail_hist) >= 2 else set()
    if stuck and stuck <= diagnosed:      # the other strategy was already tried on exactly these
        gave_up = stuck
        break
    prompt = root_cause_prompt(stuck) if stuck else plain_fix_prompt(report)
    apply(await model(prompt))
    diagnosed |= stuck
    report = run_everything()
    fail_hist.append(failing_names(report))
```

## ⚠️ نکات حیاتی / Pitfalls
- «تست را عوض نکن» به‌عنوانِ قاعدهٔ مطلق، حلقه را در همین حالت قفل می‌کند. قاعدهٔ درست: تستی که **قبول بود** باید با همان نام بماند و قبول شود؛ تستِ ردشده را می‌شود با همان نام اصلاح کرد — و گزارش کرد.
- حدسِ ماشینی «علتِ احتمالی» است، نه حکم؛ همان‌طور هم نوشته شود.
- ایست فقط روی زیرمجموعه‌بودنِ ردشده‌ها در «قبلاً ریشه‌یابی‌شده» باشد، نه روی «تعداد کم نشد» — ردشدنِ تازه یعنی وضعیت عوض شده و یک دورِ دیگر می‌ارزد.

## 🔁 چطور در جای دیگر اعمال کنیم / How to Apply Elsewhere
- هر agent ِ خودترمیم (CI autofix، «fix until green»، lint-fix با مدل): پیش از هر دور بپرس «چه چیزی نسبت به دورِ قبل عوض شد؟»؛ اگر هیچ، همان پرامپت را نفرست.
- هر جا خروجیِ ابزار برای مدل کوتاه می‌شود: استخراجِ ساخت‌یافته را روی متنِ کامل انجام بده.
