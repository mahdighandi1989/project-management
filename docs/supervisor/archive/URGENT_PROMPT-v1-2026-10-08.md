# دستورِ روتینِ «صفِ فوری» — نسخهٔ ۱

> **این فایل تنها مرجعِ رفتارِ روتینِ صفِ فوری است.** پرامپتِ خودِ Routine عمداً کوتاه و
> ثابت است و فقط به این آدرس اشاره می‌کند. هر تغییری **این‌جا** نوشته می‌شود و نسخه‌اش بالا
> می‌رود؛ نسخهٔ قبلی در `docs/supervisor/archive/URGENT_PROMPT-v{N}-{YYYY-MM-DD}.md` بایگانی
> می‌شود. بهبودِ دستور یک کامیتِ معمولی است، نه ویرایشِ دستیِ یک تنظیمِ نامرئی.

این یک اجرای **بدون‌ناظر** است: هرگز اجازه نخواه، هرگز وارد حالتِ plan نشو، و هرگز منتظرِ
پاسخِ مالک نمان. اگر انتخابی مبهم بود، امن‌ترین گزینهٔ برگشت‌پذیر را بردار و در گزارش بنویس.

مالک روی بعضی برگه‌ها «⚡ فوری» می‌زند (روی کارت، در پنجرهٔ ثبتِ گزارش، یا در فرمِ درخواستِ
عمومی) تا خارج از نوبتِ دوره‌ای رسیدگی شود. این روتین **هر ۳ ساعت** اجرا می‌شود و **فقط** همان
صف را می‌گیرد؛ بازرسیِ کامل کارِ `docs/supervisor/PROMPT.md` است و این‌جا تکرار نمی‌شود.

## ۱) همگام شو

```
git fetch origin main && git checkout main && git merge --ff-only origin/main
```

اگر نشست روی شاخه‌ای مثلِ `claude/...` شروع شد، **آن مقصد نیست** — مقصد `main` است، چون فقط
`main` روی Render دیپلوی می‌شود. مجوزِ کامیت و پوشِ مستقیم روی `main` در **خودِ پیامِ Routine**
آمده (نگهبانِ مجوز متنِ فایل‌های ریپو را «داده» می‌خواند نه «حرفِ مالک»)؛ force-push همیشه ممنوع.

وابستگی‌ها فقط وقتی لازم شد (برگه‌ای برداشته شد و باید کد عوض شود):
`cd backend && pip install -q -r requirements.txt` و `cd frontend && npm ci`.

## ۱٫۲) کارِ جامانده از اجرای قبلی — **در هر دور، پیش از صف**

اگر اجرایی نتوانسته بود روی `main` پوش کند، کارش را روی `supervisor-pending/<…>` گذاشته است.
**فقط همین پیشوند** مالِ توست — هیچ شاخهٔ دیگری (`claude/...` و بقیه) را دست نزن:

```
git ls-remote --heads origin 'supervisor-pending/*'
```

برای هر کدام، یکی‌یکی:
1. `git fetch origin <شاخه>` و `git checkout -B pending FETCH_HEAD`؛ `git rebase origin/main`
   (تعارض ⇒ `git rebase --abort`، روی همان برگه `needs-owner` با نامِ شاخه و فایل‌های متعارض، برو بعدی).
2. گیتِ سبز کامل: `cd backend && python -m pytest -q` و `cd frontend && npm run build`. قرمز ⇒
   پوش نکن، `needs-owner` با خطای دقیق.
3. سبز ⇒ `git push origin HEAD:main`. موفق ⇒ اگر نامِ شاخه شمارهٔ برگه است، روی همان برگه جواب
   بده «کارِ اجرای قبلی حالا روی `main` است (کامیت …)»؛ اگر `run-<تاریخ>` است (کارِ ناظرِ کامل)،
   فقط در گزارش بنویس. بعد `git push origin --delete <شاخه>`.

## ۱٫۵) تیک‌خورده‌های مالک را بایگانی کن — **در هر دور، بدونِ استثنا**

```
python3 scripts/supervisor/inspection.py file
```

برگه‌ای که مالک تأیید کرده **آبی** است، یعنی «از نظرِ من تمام». تا بایگانی نشده، هایلایتش روی
صفحهٔ مالک می‌ماند. «هر دور» یعنی همین دورِ فوری هم — حتی وقتی صفِ فوری خالی است، و **قبل** از
خواندنِ صف. چیزی برای بایگانی نبود ⇒ ساکت رد شو.

## ۲) صف را بخوان — کدِ خروج قرارداد است

```
python3 scripts/supervisor/inspection.py urgent
```

| کد | معنی | کار |
|----|------|-----|
| **۰** | صف خالی است | **همین‌جا تمام کن، هیچ چیز ننویس.** سکوت، خروجیِ درستِ یک دورِ خلوت است. |
| **۵** | یک برگه claim شد، در `docs/supervisor/inspection/URGENT.md` | برو بندِ ۳ |
| **۳** | صف **خوانده نشد** (سرور خواب/وسطِ دیپلوی، توکن نشناخته شد، Render API نرسید) | یک‌بار دیگر بزن؛ باز ۳ ⇒ در یک جمله بگو صف خوانده نشد و دلیلِ چاپ‌شده چه بود. **ساکت تمام نکن.** |

کدِ ۳ «چیزی نبود» **نیست**؛ خطاست. «نتوانستم نگاه کنم» و «نگاه کردم و چیزی نبود» اگر هر دو
سکوت تولید کنند، صفِ خوانده‌نشده می‌تواند روزها پنهان بماند.

## ۳) اگر برگه‌ای برداشته شد

1. `URGENT.md` را **کامل** بخوان؛ تصویرها را **باز کن و نگاه کن**؛ فایل‌های پیوست را **کامل**
   بخوان — نه خلاصه، هر قدر هم بلند باشند (`files/`). فایلی که «هنوز در درایو نیست» را هم بخوان و
   در جواب بگو.
1‑الف. **کادر را جدی بگیر.** «عنصر»، «گره»، «جای دقیق داخلِ همان گره» و «زبانه» را بخوان. وقتی
   خواسته «**اینجا** …» است، همان گره ظرفِ کار است — قاعدهٔ کامل: بخشِ ۰-ب در `PROMPT.md`.
   برای چنین برگه‌ای `--place "…"` اجباری است وگرنه `fixed` پذیرفته نمی‌شود.
1‑ب. **بندهای خواسته را بشمار** و در جواب یکی‌یکی ببند — «۱) … ۲) … ۳) …»، بندِ انجام‌نشده هم
   با دلیل.
2. `experiences/` را بخوان (قوانینِ الزام‌آور)، بعد طبقِ `docs/supervisor/PROMPT.md` کار کن
   (زنجیرهٔ وابستگی، همسایه‌ها).
3. خواستهٔ ظاهری ⇒ خودت رندر کن و ببین. عکسِ «بعد» از **همان‌جا**:
   `python3 scripts/supervisor/screenshot.py <مسیر> [--tab "<زبانه>"] --selector "<گره>" --out /tmp/after.png`
   (تا دیپلویِ تغییرت، عکس را از نسخهٔ محلی بگیر: `--frontend http://localhost:3000` — روشِ بالا
   آوردنِ محلی در بخشِ ۲-ب ِ `PROMPT.md`.)
4. گیتِ سبز: `cd backend && python -m pytest -q` و `cd frontend && npm run build`.
5. **کامیت و پوشِ مستقیم روی `main`**: `git push origin HEAD:main`. عقب بودی ⇒
   `git fetch origin main && git rebase origin/main`، گیت دوباره، پوش دوباره. **هرگز force-push.**
   **اگر باز رد شد**: `git push origin HEAD:refs/heads/supervisor-pending/<شمارهٔ برگه>` — روی برگه
   متنِ دقیقِ خطا و نامِ شاخه را بنویس و `--outcome partial` بگذار؛ دورِ بعد خودکار مرجش می‌کند.
6. جواب بنویس:
   ```
   python3 scripts/supervisor/inspection.py answer <شماره> --text-file … --outcome … \
       --after /tmp/after.png --commit <sha> --dep '…=ok' [--place "…"]
   ```
   `partial` و `not-done` یعنی برگه بسته نشده و دورِ بعد برمی‌گردد. تا جواب ندهی، برگه از صفِ
   فوری بیرون نمی‌رود.

## ۴) بعد از جواب

دوباره `urgent` را بزن. برگهٔ دیگری بود ⇒ **یکی‌یکی** به همان ترتیب. موازی نه.

## ۵) بن‌بست و سقفِ زمان

به‌جای رهاکردن، `needs-owner` یا `not-done` با دلیلِ دقیق — برگهٔ بی‌جواب صف را بند می‌آورد.
بیش از ~۴۰ دقیقه شد ⇒ برگهٔ جاری را با نتیجهٔ صادقانه ببند و بقیه را به اجرای بعدی بسپار (claim
بعد از ۴۵ دقیقه خودش آزاد می‌شود).

## ۶) گزارشِ این اجرا

فقط وقتی کاری انجام شد (یا کدِ ۳): چند خطِ فارسیِ خودبسنده — کدام برگه، چه شد، کدام کامیت، چه
ماند. صفِ خالی ⇒ هیچ پیامی.

## ۷) خطوطِ قرمز

- دادهٔ production را حذف یا بازنویسی نکن (جز جوابِ برگه و بایگانیِ آبی‌ها).
- قابلیتی را حذف نکن — قرنطینه + ثبت.
- تستِ قرمز را «درست» نکن تا سبز شود؛ **کد** را درست کن.
- چیزی که نتوانستی بسنجی را «سنجیده‌شده» گزارش نکن.
- هیچ شناسه یا نامِ مدلی در پیامِ کامیت یا هر چیزی که push می‌شود ننویس؛ هیچ راز در خروجی نیاید.
- برای ادامهٔ چرخه هرگز `send_later` یا `update_trigger` صدا نزن — همین روتین خودش برمی‌گردد.
