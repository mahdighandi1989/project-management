## ۱. هدف
پایشِ مخازنِ GitHub با AI و بستنِ چرخهٔ «ببین ⇐ بفهم ⇐ کار بساز ⇐ انجام بده ⇐ مطمئن شو». اصولِ طراحی (از docstring ِ ماژول‌ها):
- **پرامپتِ قوی و یک‌شکل** برای همهٔ مسیرها (`oversight_strong_prompt.py`): هدف، محلِ دقیق `file:line`، هدفِ پروژه، استک، وابستگی‌ها،
  معیارهای پذیرش (AC)، گام‌ها، دستورهای راستی‌آزمایی، ریسک‌ها.
- **تأییدکنندهٔ مستقل از اجرا** (`oversight_verifier.py`): نمی‌داند کار چطور انجام شد؛ فقط مخزن را با AC می‌سنجد؛ «انجام‌شده» فقط
  پس از `confirmation_streak` بار تأییدِ پیاپی.
- **بی‌خلاصه** در استخراجِ پیوست‌ها (`oversight_extraction.py`)، **بافرِ تلگرام** تا «ارسال» هیچ تسکی نمی‌سازد.
- قاعدهٔ مالک (کامیت `028ea8f3`، 2026-06-14): «اجرای خودکار خاموش = هیچ تغییری در GitHub رخ ندهد».

## ۳. نقشهٔ صفحه
`frontend/src/app/oversight/page.tsx` (~۱۱٬۲۰۰ خط). سرِ صفحه: بازخوانی، دکمه‌های backfill ِ AC، کارت‌های وضعیت، انتخابِ چندمدلی.
- **تحت نظارت** — کارتِ هر پروژه (`WatchedCard`): یادداشت/برچسب، زمان‌بندی، سطحِ خودکاری، عمق و وزنِ اسکن، پرچم‌های v5، چرخهٔ عمر،
  نشانی‌های runtime و Auth Recipe، auto-loop، اسکنِ سریع/عمیق (با پنجرهٔ پیشرفت)، Bulk Verify، سیاههٔ قابلیت‌ها، کیفیتِ پرامپت، Claude Runner، Codex.
- **مخازن GitHub** — فهرست (با کش) و افزودنِ تکی/گروهی.
- **ایده/مشکل** — پیوست (TaskFilePicker)، شباهت هنگامِ تایپ، تولیدِ پرامپت (همگام یا کارِ پس‌زمینه)، مدلِ بینایی، ذخیره، ادغامِ تکراری.
- **تسک‌ها** — فهرست/کانبان، فیلتر و جست‌وجو و ترجیحاتِ نما، اجرا (AI / Claude)، verify، تاریخچه، بازتولید/برگشتِ پرامپت، پیوست‌ها،
  «اجرا با AI» روی صفحهٔ پروژه (smart-chat ⇐ apply-action ⇐ PR) با auto-loop.
- **گزارش‌ها** — فهرست، خوانده/پرچم، خروجیِ JSON/MD، شواهد.
- نشانی: `?tab=watched|repos|ideas|tasks|reports` و `&watched=<id>` (از دکمه‌های تلگرام).

## ۴. جریانِ کار
1. **ایده ⇐ پرامپت:** `idea_to_prompt` (`oversight_service.py`)؛ پیوست‌ها با `_resolve_attachments_for_idea`؛ چندمرحله‌ای؛ متنِ نهایی با `build_strong_prompt`.
   `POST /api/oversight/tasks/from-idea` و `idea-to-prompt-job` (پیشرفت: `/progress/{id}`).
2. **پرامپت ⇐ تسک:** `create_task` — اعتبارِ عنوان، استخراج و غنی‌سازیِ AC، دروازهٔ تکراری، ذخیره (و همگام‌سازی با `prompt/` فقط اگر runner روشن است).
3. **اجرا:** بخشِ ۶. 4. **تأیید:** بخشِ ۷. 5. **گزارش:** `OversightReport` با هر اجرا/تأیید؛ تلگرام از طریقِ `notify_event`.
**وضعیت‌های تسک:** pending · suggested (از اسکن) · running · awaiting_review · done · failed · abandoned (پایانِ auto-loop) — به‌علاوهٔ
`verification_status` (pending / applied_externally_pending_verify / partial / done / regressed / needs_clarification)، `external_status` و `archived`.

## ۵. اسکنِ عمیق
`oversight_deep_scan_service.run_deep_scan`: ساختارِ مخزن از GitHub ⇐ انتخاب و خواندنِ فایل‌ها (۲۵ تا ۲۰۰۰ بسته به عمق) ⇐ تا ۱۲ گذرِ AI ⇐ اسکن v5
(سیاهه، هدف‌ها، کهنه‌یابی، مستندِ قابلیت‌ها، کشفِ runtime با Playwright، پیامد، انسجام، ضدالگوها، ممیزیِ اعلان، دلتا) ⇐ یافته‌ها ⇐ ادغام ⇐ تا ۲۰۰ تسکِ
`suggested` ⇐ ذخیره و بستهٔ PDF و تلگرام. **هزینه:** حدودِ ۹۷ فراخوانیِ مدل + تا ۲۰۰ فراخوانیِ چک‌لیست برای یک اسکنِ عمیق با یک مدل.
اسکنِ سریع (`POST /scan/{id}`): یک فراخوانی، تا ۸ تسک.

## ۶. اجرا
- **Claude Auto-Runner:** workflow ِ `.github/workflows/claude-auto-task.yml` در مخزنِ هدف + سه secret (`CLAUDE_CODE_OAUTH_TOKEN`، `OVERSIGHT_EXTERNAL_TOKEN`،
  `OVERSIGHT_BACKEND_URL`)؛ اجرا فقط با workflow_dispatch؛ تسک از `/api/external/prompts/*` گرفته و پس از push، `complete` ⇐ `_verify_then_chain`
  (تأیید ⇐ تسکِ بعدی، یا تکرار تا ۳ بار، یا TO-DO و آرشیو).
- **`/tasks/{id}/run` و `auto_via_pr`:** فقط **ارزیابی** با AI (README و فهرستِ فایل‌ها) — هیچ تغییرِ کد یا PR نمی‌سازند (ایرادِ باز، بخش ۱۲).
- **`auto_via_projects_page`:** خودفراخوانیِ smart-chat ِ بازرس (پس از رفعِ امروز، با کلیدِ ماشینی از دیوارِ ورود می‌گذرد).
- **دستی:** کپیِ پرامپت + «اعمال شد بیرون» یا ثبتِ PR.

## ۷. تأیید (Verify)
ایستا (خواندنِ فایل‌ها، grep برای هر AC، رأیِ JSON ِ AI) + زمانِ اجرا (probe ها، verify ِ کدآگاه روی ۶۰ کامیتِ آخر، probe ِ لاگ) + اورکستراتورِ v6
(هر AC جدا، با کش). قاعدهٔ نهایی: done فقط بی‌`remaining_parts` و با streak ِ کافی ⇒ آرشیوِ خودکار؛ partial ⇐ awaiting_review؛ regressed ⇐ pending.

## ۸. کارهای زمان‌بندی‌شده
حلقهٔ ۶۰ثانیه‌ای `oversight_scheduler_loop` (به ترتیب): پاک‌سازی‌ها، backfill ِ AC (هر ۶ ساعت)، sweeper ِ verify ِ خارجی، برای هر پروژه: اسکنِ عمیقِ
موعدرسیده، verify ِ دوره‌ای، اجرای خودکارِ تسک‌های `auto_via_*`؛ گزارشِ روزانه (۰۸ تهران)، فهرستِ تلگرام، بررسیِ موجودیِ AI، یادآورها.
APScheduler: کشفِ خودکارِ مخزن هر ۶۰ دقیقه.

## ۹. ذخیره‌سازی

این‌ها رفتار یا هزینه را تغییر می‌دهند؛ بدونِ تصمیمِ مالک دست نخوردند:
1. **`/run` و «apply» و `auto_via_pr` کد را تغییر نمی‌دهند** ولی می‌توانند تسک را از حدسِ README «done» کنند (بی‌گذر از streak). پیشنهاد: done فقط از verifier.
2. **تأییدِ بیش‌ازحد آسان‌گیر:** یک probe ِ موفق (حتی probe ِ مصنوعیِ «صفحهٔ اصلی باز شد») not_done را done می‌کند؛ probe های static/test روی Render رد می‌شوند؛ runner از streak معاف است.
3. **runner ِ «فقط دستی» وقتی اجرای خودکار خاموش است کار نمی‌کند** (دروازهٔ `028ea8f3` نصب/اجرای تکی را هم می‌بندد) — تعارضِ دو خواستهٔ مالک.
4. **رشدِ بی‌حدِ دیسکِ ۱GB:** گزارش‌ها، `extractions.json` با متنِ کامل، تاریخچهٔ پرامپت‌ها، آپلودها، بسته‌های PDF، اسکرین‌شات‌ها و `inspector_context`؛ و `_write_json` خطای «دیسک پر» را می‌بلعد. با قاعدهٔ ۶ (فایلِ حجیم ⇐ گوگل درایو) ناسازگار است.
5. **نوشتنِ همگامِ کلِ `tasks.json` در هر تغییر** روی حلقهٔ رویداد (کندیِ `/health`).
6. **اسکنِ عمیق داخلِ نوبتِ زمان‌بند** await می‌شود (ده‌ها دقیقه بقیهٔ کارها منتظر)؛ تایم‌اوتِ کلی ندارد؛ هم‌زمانیِ دو اسکن محافظت نمی‌شود.
7. **تکراری‌یابیِ اسکن** هم یافته‌های واقعیِ متفاوت در یک فایل را یکی می‌کند و هم تسک‌های لغوشده را دوباره می‌سازد؛ کهنه‌یابی فقط فایل‌های خوانده‌شده را می‌بیند (مثبتِ کاذب).
8. **اجرای ناموفق در GitHub Actions هرگز تطبیق داده نمی‌شود** (نه webhook نه polling) و تسکِ `failed` دوباره انتخاب می‌شود.
9. **شاخهٔ `main` سخت‌کد** در workflow و dispatch (مخزنِ `master` شکست می‌خورد).
10. **probe های API می‌توانند روی production POST/PUT/DELETE بزنند**؛ و توکنِ OAuth ِ مالک به‌عنوانِ secret در هر مخزنِ پایش‌شده کپی می‌شود.
11. **auto-loop برای `auto_via_*`** هرگز `followup_round` را بالا نمی‌برد (حلقهٔ بی‌پایان در هر بازه).
12. **کشفِ خودکارِ مخزن** هیچ مخزنی اضافه نمی‌کند (`created_at` کپی نمی‌شود) — یا با سقفِ ۰ همه را با خودکاریِ کامل اضافه می‌کند.
13. **مستنداتِ ریشه کهنه‌اند:** README/ARCHITECTURE/ROADMAP اتاق فرمان را نمی‌شناسند و ورود با گوگل را «بدونِ احراز هویت» می‌نویسند.

### به‌روزرسانیِ ۲۰۲۶-۱۱-۱۵ (ج) — ایرادهای کوچک‌ترِ صفحه (از بازبینیِ فرانت)

### به‌روزرسانیِ ۲۰۲۶-۱۱-۱۵ (ه) — بایگانیِ گزارش‌ها و نوشتنِ پس‌زمینه
